## Phase 1: Correctness bugs (must fix — silent wrong results or broken code)

These are bugs, not optimizations. They produce wrong results or crash.

### 1A. PooledConnection wrapping leak (BOTH TEAMS flagged)

- **What:** `get_connection()` returns PooledConnection to pool, next borrow wraps it again. After N cycles: N layers of `__getattr__` proxy. Unbounded growth.
- **Where:** `src/db_pool.py:257` — the `finally` block in `get_connection()` context manager
- **Impact:** Slow memory leak + performance degradation in long-running processes (dashboard, LaunchAgents)
- **Fix:** Change `pool.return_connection(conn)` to `conn.close()` — PooledConnection.close() already correctly returns `self._conn` (raw connection) to the pool
- **Complexity:** Low (1 line)
- **Tests:** Add test that borrows/returns 100 times, verify no nesting

### 1B. importance_engine word count logic is backwards

- **What:** `if word_count > 50` comes before `elif word_count > 100` — the elif is dead code. 100+ word memories get +0.1 instead of intended +0.2.
- **Where:** `src/importance_engine.py:71-74`
- **Impact:** Systematically undervalues substantial memories by 0.1. Compounds with decay over time.
- **Fix:** Swap order: `if word_count > 100: score += 0.2; elif word_count > 50: score += 0.1`
- **Complexity:** Low (2 lines)
- **Tests:** Add test for word_count > 100 getting 0.2 bonus

### 1C. async_consolidation wrong parameter + wrong attributes

- **What:** `process_consolidation_queue()` passes `session_path=` but consolidator expects `session_file=`. Also accesses `result.new_count` etc. but ConsolidationResult has `memories_extracted`, `memories_saved`, `memories_deduplicated`.
- **Where:** `src/async_consolidation.py:239-246`
- **Impact:** Entire async consolidation pipeline is broken. Every queued session enters fail-retry loop forever.
- **Fix:** Change kwarg name + attribute names to match actual API
- **Complexity:** Low (3 lines)
- **Tests:** Add basic test for `process_consolidation_queue`

### 1D. shared_knowledge.py is entirely broken (syntax errors)

- **What:** Every `with get_connection()` block has corrupted indentation: `co    nn.execute` instead of `conn.execute`. Module fails to import.
- **Where:** `src/shared_knowledge.py` — ~28 corrupted lines throughout
- **Impact:** Currently zero (nothing imports it). But it's a shipped file.
- **Fix:** Delete the file (it's dead code with no imports, no tests) OR fix all corrupted whitespace
- **Complexity:** Low (delete) or medium (fix)
- **Recommendation:** Delete. If the feature is needed later, write it from scratch.

## Phase 2: Performance hot path (measurable improvements at current scale)

### 2A. Maintenance reads all files 4× per run

- **What:** `run()` calls 4 functions, each does its own `client.list()` or `client.search()`, each reading all 1,497 files. Plus N+1 update pattern in `apply_decay_to_all` (574 re-reads + 574 writes).
- **Where:** `src/daily_memory_maintenance.py:58-96` (orchestration), individual calls at lines 112, 161, 265, 333
- **Impact:** ~6,000 file operations per daily run. Should be ~2,100.
- **Fix:** Read all memories once at top of `run()`, pass list to each step. For decay, write directly via `_write_memory()` instead of through `update()` (which re-reads).
- **Complexity:** Medium (refactor run() signature + 4 step functions)

### 2B. health_check reads every file twice

- **What:** Within its file loop, reads file with `read_text()` for structural check, then immediately reads again via `_read_memory()` for YAML parse.
- **Where:** `src/daily_memory_maintenance.py:340-367`
- **Impact:** Doubles I/O cost of health checking (~0.7s wasted)
- **Fix:** Have `_read_memory()` accept optional pre-read string, or just use `_read_memory()` and catch exceptions for corruption detection
- **Complexity:** Low

### 2C. BM25 IDF recomputed every search

- **What:** `compute_idf()` tokenizes all documents and calculates inverse document frequency on every `hybrid_search()` call. Result is identical between calls (only changes when corpus changes).
- **Where:** `src/hybrid_search.py:181-183`
- **Impact:** 66ms per search (45% of BM25 cost). Wasted on repeated identical computation.
- **Fix:** Cache IDF dict with corpus fingerprint (len + hash of IDs). Recompute only when fingerprint changes.
- **Complexity:** Low

## Phase 3: Architecture improvements (scaling + reliability)

### 3A. 7 intelligence.db modules bypass connection pool

- **What:** 7 modules that share `intelligence.db` use raw `sqlite3.connect()`, missing WAL mode, retry logic, and timeout configuration that the pool provides.
- **Where:** `access_tracker.py`, `encoding_depth.py`, `entity_extractor.py`, `intelligence_orchestrator.py`, `memory_health.py`, `retrieval_forgetting.py`, `daily_episodic_summary.py`
- **Impact:** SQLITE_BUSY under concurrent access (dashboard + hook + LaunchAgent)
- **Fix:** Migrate each to `get_connection()` or `get_pool()`
- **Complexity:** Medium (7 files, need to handle init/close patterns)

### 3B. VectorStore non-atomic save

- **What:** `_save()` writes FAISS index, then writes metadata JSON. Crash between them = index/metadata desync → wrong search results.
- **Where:** `src/vector_store.py:253-260`
- **Impact:** Silent wrong results if crash during the ~1ms write window. Rare but unrecoverable without rebuild.
- **Fix:** Write metadata to temp file first, then `os.replace()` atomically. Or combine into single SQLite store.
- **Complexity:** Low (temp + rename pattern)

### 3C. list() silently swallows parse errors with zero logging

- **What:** `except Exception: continue` in `list()` means a corrupt memory file silently disappears from all searches, stats, and maintenance.
- **Where:** `src/memory_ts_client.py:237-242`
- **Impact:** Data loss is invisible. User never knows a memory was dropped.
- **Fix:** Add `logger.warning(f"Skipping unparseable memory: {memory_file}: {e}")` in the except block
- **Complexity:** Low (1 line)

### 3D. Metadata index for search/list (the O(n) → O(log n) fix)

- **What:** Every `search()` and `list()` reads ALL .md files from disk, parses YAML, then filters in Python. No index exists.
- **Where:** `src/memory_ts_client.py:224-258` (list), `385-433` (search)
- **Impact:** 0.5s per cold call at 1,497 memories. Scales linearly. At 5,000 memories → ~2s per call.
- **Fix:** Build thin SQLite metadata index mirroring frontmatter fields. Invalidate on write (single write path: `_write_memory`). Query index for filtered searches.
- **Complexity:** High (new module, invalidation logic, migration)
- **Note:** This is the only fix that changes scaling characteristics. Everything else is constant-factor.

## Phase 4: Cleanup + defense

### 4A. 85 exact-duplicate memories

- **What:** 85 memories with byte-identical content but different IDs. 5.7% of the store.
- **Impact:** 25ms added to every scan + BM25 scoring inflation
- **Fix:** One-time dedup script: group by content hash, keep oldest/highest-importance, archive rest. Then investigate why dedup pipeline didn't catch them.
- **Complexity:** Low (script)

### 4B. apply_decay N+1 update pattern

- **What:** 574 memories get individually re-read then written during decay. Already has parsed Memory objects in hand.
- **Where:** `src/daily_memory_maintenance.py:117-132`
- **Impact:** 2-3 min wasted I/O at 3 AM daily
- **Fix:** Write directly via `_write_memory()` on already-parsed objects
- **Complexity:** Low
- **Note:** Subsumed by fix 2A if maintenance refactored

### 4C. non-atomic TOOLS.md write

- **Where:** `src/correction_promoter.py:168`
- **Fix:** Write to temp, then `os.replace()`
- **Complexity:** Low

### 4D. 24 untested source modules

- **What:** No test files for: `async_consolidation`, `shared_knowledge`, `correction_promoter`, `confidence_scoring`, `config`, `conversation_compactor`, and 18 others.
- **Priority test targets:** `async_consolidation` (broken), `correction_promoter` (writes system files), `confidence_scoring` (used in API), `config` (foundational)
- **Complexity:** High (24 modules × 10-15 tests each)
- **Note:** Not all need tests immediately. Focus on write-path and API-path modules.

## What was killed (for the record)

### Performance kills (11)
1. Import time slow (numpy/sklearn) — 36ms, once per process
2. Module-level numpy import — once per process, lazy from api.py
3. Unbounded `_embeddings_cache` — actually bounded by LRU at 1,000
4. Unbounded `embedding_manager` cache — also bounded at 1,000
5. api.py TTL cache holds all memories — ~1.5MB, 5s TTL is fine
6. Dashboard cache holds memories — local tool, <2MB, manually refreshable
7. prospective_triggers raw connects — own DB, no contention
8. generational_gc holds self.conn — own DB, no contention
9. PageRank O(V*E) — bounded by 20 iterations, near-empty graph
10. session_history_db raw connects — own DB, code hygiene not perf
11. ContextBudgetOptimizer re-scores — <1ms, pure arithmetic

### Reliability kills (7)
1. row_factory contamination — no mismatch exists, all use sqlite3.Row
2. archive() non-atomic — self-healing (duplicate resolved on next attempt)
3. ast.literal_eval crash — swallowed by list() catch, data always written valid
4. Global _model not thread-safe — single-threaded process
5. IntelligenceDB holds pool connection — pool size accommodates it
6. ConsolidationQueue race condition — single-worker system
7. String session_path type mismatch — subsumed by kwarg name bug
